技术博客的阅读体验，很少由某一个惊艳的设计决定。更多时候，它取决于一组不起眼的小选择。

这篇笔记记下我在搭站时反复调整的几处排版细节。它们都不复杂，但叠加起来，会让长文明显更愿意被读下去。

## 1. 正文的行宽比字号更重要

字号从 16px 调到 17px，读者未必能察觉；但一行从 100 个字符缩到 70 个字符，阅读节奏会立刻变好。

中文正文我控制在约 `36–42em` 的宽度，配合稍大的行高：

```css
.prose {
  max-width: 68ch;
  font-size: clamp(1rem, 0.97rem + 0.15vw, 1.075rem);
  line-height: 1.9;
}
```

`ch` 是相对字符宽度的单位，比固定像素更能适应字体变化。行高也建议用无单位数值，让不同字号自动继承合理间距。

## 2. 标题需要「呼吸」，但不需要每级都很大

标题层级如果只靠字号拉开，很容易变成一堵墙。我的做法是：

- 正文和标题之间留出更大的上边距，下边距收紧；
- 用字重、颜色和少量留白区分层级；
- 二级标题加一条不抢眼的间距，而不是分割线。

```css
.prose h2 {
  margin-top: 2.35em;
  margin-bottom: 0.75em;
}

.prose h2 + p {
  margin-top: 0.55em;
}
```

相邻选择器把「标题后第一段」单独收紧，能让标题和正文形成一组，减少松散感。

## 3. 链接不需要默认变蓝

链接如果只靠颜色区分，在长文里会不够稳定。我用下划线表达「可点击」，用蓝色表达悬停状态：

```css
.prose a {
  color: var(--ink);
  text-decoration: underline;
  text-decoration-color: var(--line);
  text-underline-offset: 0.22em;
}

.prose a:hover {
  color: var(--blue);
  text-decoration-color: var(--blue);
}
```

下划线是最稳定的可访问性信号。颜色可以作为辅助，但不要成为唯一的区分方式。

## 4. 代码块是另一种阅读模式

代码块内的读者不是在「读文章」，而是在「扫描结构」。所以它需要更大的对比度、更紧凑的行高，以及和正文明显不同的容器。

我倾向让代码块始终保持深色：

- 它像一个独立的工作台；
- 与正文形成明确分区；
- 不用同时维护两套高亮样式。

唯一要注意的是行内代码不要和正文抢戏，所以只保留浅背景和等宽字体，不加边框和阴影。

## 5. 留白要成组，不要均匀

均匀的间距会让页面显得平，也会让读者失去分组线索。比起「每个元素都间隔 24px」，更好的做法是：

- 同一组内的元素靠近；
- 组与组之间拉开；
- 页面边缘的留白比内部间距更大。

这也是为什么我更喜欢在父容器上使用 `gap` 和 `padding`，而不是给每个子元素都写一个 margin。

## 尾声

这些规则没有一条是绝对的。排版最终服务于内容：一篇快速记录和一篇长文，适合的节奏并不相同。

但当你不知道从哪里开始时，先把行宽、行高和分组做对，通常已经能解决大部分「看起来不太舒服」的问题了。
